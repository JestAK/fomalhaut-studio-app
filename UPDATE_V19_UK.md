# Оновлення 19 — розподіл субтитрів і видалення матеріалів

Версія сервера: 2026.10.28.19. Пакет містить усі попередні зміни.

## Встановити поверх v18

```bash
mkdir -p ~/releases/v19
cd ~/releases/v19
curl -fL --retry 3 https://fomalhaut-studio.fomalhautdub.chatgpt.site/Fomalhaut-Studio-v19.zip -o release.zip
unzip -q release.zip
cd Fomalhaut-Studio
cp ~/releases/v18/Fomalhaut-Studio/.env .env
sudo bash ops/update.sh
curl -fsS https://fomalhaut-team-app.duckdns.org/api/health
```

Очікувана версія: `2026.10.28.19`. Якщо .env не знайдено, зупиніться: потрібно скопіювати його з фактично встановленого релізу. Не створюйте нові секрети. Не виконуйте `docker compose down -v`. Оновлення зберігає постійні томи й створює резервну копію БД. Після оновлення закрийте й відкрийте Telegram Mini App; у браузері Ctrl+Shift+R.

## Новий розподіл

- Після перевірки одержувачів файли спочатку зберігаються на сервері. До підтвердженого розподілу у групі вони не публікуються.
- Завдання акторів і черга публікації зберігаються однією операцією. Кожному актору — своє завдання з його файлами. Спільні файли доступні всім вибраним одержувачам.
- У гілку надходить зведення: назва проєкту й SxxExx, хештег СофтСаби, нікнейми без @ і кількість реплік, хештег серії. Далі — альбом документів. У великій пачці кожні 10 документів утворюють окремий альбом; один документ надсилається окремо.
- SRT/VTT: одна часова репліка = один запис, незалежно від кількості рядків тексту. ASS/SSA: рахуються Dialogue, не Comment. Для ZIP та непідтримуваних форматів чесно вказано «кількість реплік не визначена».
- Назва індивідуальних субтитрів містить нік актора, а не рольовика. Для спільного файла — ніки вибраних акторів. Кілька файлів з однаковою базовою назвою отримують числовий суфікс.
- Після підтвердження показується таблиця створених завдань. За автоматичного режиму вони активні; якщо адмін установив ручний запуск озвучення, видно очікування цього запуску. Ручні обмеження не обходяться.
- Особисте сповіщення про активне завдання зберігається в застосунку. Покажчик непрочитаного в ПП надходить учасникам, які натиснули Start у бота й увімкнули сповіщення.
- Черга показує помилки у завданні рольовика. Після неоднозначної відповіді Telegram пачка автоматично не повторюється: спочатку перевірте гілку, щоб не створити дублікати.

## Виправити попередню пачку

Відкрийте завдання рольовика → «Редагувати розподіл і файли» (або «Роздати пачку субтитрів», якщо розподілу ще немає). Уже додані файли підставляються. Перевірте одержувачів та підтвердьте. Нові копії старих документів не надсилаються: бот редагує свої наявні повідомлення. Файли, які бот не може редагувати, покажуть помилку в черзі. Старе окреме зведення автоматично не видаляється.

## Видалення

Кнопка «Вилучити» відкриває вибір:
- «Лише з додатка» — повідомлення у групі залишається.
- «З додатка і з Telegram» — спочатку бот видаляє повідомлення; лише після підтвердження прибирає матеріал з додатка.

Для ще не опублікованого файла доступне лише видалення з додатка. Якщо Telegram відмовив, матеріал залишається, а застосунок показує помилку. Telegram Bot API має обмеження: deleteMessage зазвичай доступний лише для повідомлень молодших за 48 годин і за наявності належних прав бота. Старші повідомлення потрібно видаляти вручну в Telegram, потім прибирати матеріал із додатка.

Перевірено автоматично: три різні актори, спільний файл, активні завдання, відсутність публікації до розподілу, один альбом, правильні назви, відсутність дублювання повторного запиту, відмова у видаленні чужого файла, відмова Telegram без втрати матеріалу, успішне видалення та варіант лише з додатка. Реальні права вашого бота перевіряються після встановлення.
