# Fomalhaut Studio

Вебзастосунок і Telegram Mini App для координації української студії озвучення **Fomalhaut DUB**. Об'єднує завдання команди, матеріали серій, записи акторів і виписування правок в одному виробничому процесі.

## Можливості

- Переклад → редактура → розподіл субтитрів → озвучення → виписування та запис правок → зведення.
- Ролі користувачів, черга запитів доступу, гості, кілька ролей для однієї людини.
- Автоматичний або ручний запуск етапів і серій, індивідуальні дедлайни, календар і аналітика.
- Розподіл субтитрів за ніками та еліасами, перевірка одержувачів перед надсиланням.
- WAV/FLAC, серверне перетворення у моно FLAC, неймінг, контроль дублікатів та ітерації FIX.
- Фонові завантаження, матеріали серії, ZIP-архіви, зберігання файлів через Telegram.
- Імпорт правок із Notion зі знімками вмісту та зображень.
- Сповіщення, часові пояси, періоди «не турбувати», облік участі акторів у проєктах.

## Технології та структура

Node.js 24, JavaScript ESM, SQLite, FFmpeg, Telegram Bot API, Docker Compose та Caddy. Інтерфейс — HTML/CSS/JavaScript без UI-фреймворку. Сервер використовує вбудовані модулі Node.js без npm-залежностей.

| Каталог | Призначення |
| --- | --- |
| `dist/` | Інтерфейс, стилі, демонстраційні дані |
| `server/` | HTTP API, авторизація, SQLite, черги та інтеграції |
| `tests/` | Автоматичні тести |
| `ops/` | Оновлення, резервування та відновлення |
| `.github/workflows/` | Перевірки й автоматичне розгортання |

Застосунок розрахований на невелику команду й один серверний процес. SQLite та черга файлів не передбачають запуск кількох незалежних реплік.

## Локальна перевірка

Потрібні Node.js 24+, FFmpeg і `zip`:

```bash
npm run check
npm test
```

Для перегляду демонстраційного інтерфейсу без Telegram та серверної БД:

```bash
python3 -m http.server 8080 --directory dist
```

Відкрийте `http://localhost:8080`. Демонстрація не підтверджує роботу живих інтеграцій.

Push у `main` запускає перевірки та збирання Docker-образу. Розгортання запускається тільки після успішних перевірок і ввімкнення `DEPLOY_ENABLED`. Оновлення створює резерв БД; дані залишаються у постійних Docker volumes.

У репозиторії немає робочої `.env`, БД, записів команди чи токенів. `.env.example` містить лише приклади. Тести використовують підміни зовнішніх API; Telegram, Notion і авторизацію необхідно додатково перевіряти у власному середовищі.

Проєкт розробляється з допомогою AI за вимогами студії. Публічна версія базується на релізі v34. Ліцензію на повторне використання наразі не визначено.
