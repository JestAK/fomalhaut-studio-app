# Fomalhaut Studio v22 — аналітика, перенесення та матеріали серії

Реліз API: `2026.10.29.22`. Містить також усі зміни v21: індикатор непрочитаного, окреме прочитання, перевірку дублікатів, правильний лічильник активних завдань.

## Оновлення на вашому AWS

Виконайте у SSH, з каталогу **поточного працюючого релізу**, де лежить `.env`:

```bash
STUDIO_PREVIOUS_DIR="$PWD"
test -f "$STUDIO_PREVIOUS_DIR/.env"
```

Якщо команда не знайшла `.env`, спочатку перейдіть у каталог встановленої версії (наприклад `cd ~/releases/v20/Fomalhaut-Studio`). Не створюйте новий порожній `.env`.

```bash
mkdir -p ~/releases/v22
cd ~/releases/v22
curl -fL --retry 3 https://fomalhaut-studio.fomalhautdub.chatgpt.site/Fomalhaut-Studio-v22.zip -o release.zip
unzip -q release.zip
cd Fomalhaut-Studio
cp "$STUDIO_PREVIOUS_DIR/.env" .env
sudo bash ops/update.sh
```

Якщо копіювання `.env` не вдалося — зупиніться й виправте шлях. Скрипт оновлення створює резервну копію, зберігає наявні Docker volumes і перевідкриває Caddy з новим лімітом. Не використовуйте `docker compose down -v`.

```bash
curl -fsS https://fomalhaut-team-app.duckdns.org/api/health
```

Має бути `release: 2026.10.29.22`. Закрийте й повторно відкрийте Mini App, у браузері оновіть сторінку з Ctrl+Shift+R.

## Аналітика

Нова вкладка видима адміністраторам. Фільтр за проєктом; активні, прострочені, дедлайн за 3 дні, на перевірці; графік навантаження за етапами, таблиця людей, прогрес серій і ручні зупинки. Показники відкривають відповідні завдання. Активні — тільки «Очікується» та «У роботі»; планові не вважаються поточною роботою. Кількість завдань не вимірює складність чи якість роботи людини.

## Перенесення вже розпочатих проєктів

1. Створіть проєкт, призначте ролі та прив’яжіть гілку. Для гостей адмін створює гостьові профілі.
2. Проєкт → «Перенести прогрес». Оберіть номер серії та поточний етап. Наявну активну серію програма не перезаписує.
3. Перевірте автоматично підставлених відповідальних. Виберіть акторів і їхній фактичний стан: ще записує, ще не перевірено, правок немає, є правки, правки здано. Уточніть ітерацію актуальних фіксів.
4. Додайте індивідуальні субтитри, файли перекладу/редактури та всі потрібні записи кожного актора. У кожному полі можна мати кілька посилань. «Показати відомі боту файли» відкриває останні 500 файлів, пошук і призначення до полів. Ніки/аліаси та стандартні назви допомагають запропонувати призначення; обов’язково перевірте їх.
5. Підсумкова таблиця показує статуси та які посилання стануть справжніми файлами в завданні й ZIP. Невідомі боту та зовнішні файли залишаються посиланнями, без ZIP.
6. Натисніть «Перенести й продовжити роботу». Старі файли повторно в групу не надсилаються. Повідомлення отримують виконавці активних завдань. Дедлайни їм рахуються від перенесення. Наступні етапи — автоматично, наступна серія — вручну; режими можна змінити у виробництві.

Бот не може прочитати історію групи до свого підключення. Для старого невідомого файла: перешліть його в командну групу, поки бот працює, і використайте нове посилання; або залиште посилання на оригінал і після перенесення завантажте файл у завдання. Передавання старого файла не змінює його вміст; імпортовані записи не нормалізуються повторно. Нові завантаження акторів проходять звичайну обробку WAV/FLAC → моно FLAC.

Майстер переносить актуальний стан. Поле фіксів стосується вказаної ітерації; не змішуйте в ньому застарілі й актуальні варіанти. Історію старих ітерацій можна залишити за посиланнями в матеріалах серії.

## Матеріали серії

У кожному завданні та у виробництві серії є «Матеріали серії». Три категорії: оригінальний файл, оригінальні субтитри, українські хардсаби. Адмін окремо призначає відповідальних. Вони та адміни додають файли або HTTPS-посилання (наприклад FEX), усі учасники переглядають і завантажують файли. Посилання відкривають зовнішній ресурс і не входять до ZIP. Матеріали можна додавати на будь-якому етапі: вони не блокують виробництво. Для матеріалів створюються незалежні завдання без обов’язкового дедлайну; адмін може виставити його вручну.

## Фонові завантаження та розмір

Звичайні файли потрапляють у послідовну чергу. Пачку субтитрів також можна надіслати й закрити вікно розподілу. Значок угорі показує чергу, відсоток передавання та стан обробки. Можна переходити між сторінками; успішне завершення дає сповіщення. Нові діалоги не закриваються через завершення передачі.

Фоновість працює **в межах відкритої вкладки/Mini App**. Закриття всієї вкладки, вихід або призупинення Telegram телефоном може перервати ще не переданий файл. Після завершення передавання обробка триває на сервері. При перезапуску вкладки вибір ще не переданих файлів не відновлюється; черга сервера лишається доступною у значку завантаження. Після невизначеної помилки перевірте чергу/гілку, перш ніж повторювати надсилання.

Жорстка межа — **2 000 000 000 байтів (2000 МБ)** на один файл: перевіряється інтерфейсом, сервером, проксі та перед публікацією обробленого файла. Потрібен локальний Telegram Bot API, який уже є у Docker Compose; публічний api.telegram.org не має цього ліміту. Великі файли поза межею додавайте посиланнями. Офіційне джерело: https://core.telegram.org/bots/api#using-a-local-bot-api-server

## Перевірка

Автоматичні перевірки охоплюють ролі, збереження матеріалів, безпечні HTTPS-посилання, імпорт без повторної публікації, доступ до імпортованих файлів, переходи правок і зведення, повторне підтвердження без дублікатів та розрахунки аналітики. Перевірено інтерфейс майстра й матеріалів у браузері. Фізичне передавання файла розміром 2000 МБ на вашому AWS ще не перевірялось.
