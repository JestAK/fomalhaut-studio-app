# Правки з Notion

## Як працює імпорт
У завданні правкера під кожним актором є «Імпортувати правки з Notion». Оберіть вкладку board view за назвою та введіть точний псевдонім актора. Програма застосовує збережені фільтри й сортування цієї вкладки через Notion Views API, потім відбирає актора за полем групування колонок. Якщо колонка інша, розкрийте «Інше поле для псевдоніма» та введіть назву поля (Select / Multi-select / People / текст).

Перед прикріпленням показуються отримані картки та одержувач. «Прикріпити ці правки» вибирає статус «Є правки», але ще не сповіщає. Далі «Сповістити акторів» → перевірити підсумок → підтвердити. Копія приєднується до завдання «Запис правок»; актор відкриває її кнопкою «Переглянути правки».

Якщо інтеграція налаштована, відправлення статусу «Є правки» потребує перевіреної копії Notion. Статус «Немає правок» не потребує імпорту. Неперевірені актори лишаються в черзі правкера.

## Підключення (один раз, адміністратором)
1. У Developer portal Notion створіть внутрішню інтеграцію / internal connection для вашого workspace. Достатньо Read content. Запис у Notion програмі не потрібен.
2. Надайте цій інтеграції доступ до бази правок і сторінок, які вона використовує. Доступ лише до зовнішньої сторінки з linked view може бути недостатнім — потрібна й вихідна база.
3. Скопіюйте токен у .env на сервері, не в чат і не у фронтенд:
   ```dotenv
   NOTION_TOKEN=ntn_ваш_токен
   NOTION_DATABASE_ID=ідентифікатор_бази_з_вкладками
   ```
4. NOTION_DATABASE_ID — ID саме бази / collection view block із вкладками, а не ID звичайної сторінки «Правки» й не параметр `v=`. Відкрийте базу як повну сторінку та скопіюйте її посилання; ID — 32 шістнадцяткові символи в адресі перед `?`. Дефіси також допустимі.
5. Після редагування .env застосуйте конфігурацію за інструкцією нижче.
6. Відкрийте завдання правкера → імпорт. У списку мають з'явитися ваші board views. Якщо їх немає — перевірте ID бази й доступ інтеграції. Помилка 404 від Notion також може означати відсутність доступу.

Публікувати базу Notion в інтернеті не потрібно. Токен залишається лише на сервері.

## Застосування конфігурації

Після зміни `.env` виконайте `sudo bash ops/update.sh` з каталогу чинної програми. Якщо використовується автодеплой, змініть також `~/fomalhaut-deploy/shared.env`, щоб наступне оновлення зберегло конфігурацію. [Інструкція автодеплою](DEPLOY_GITHUB_UK.md).

## Збереження та межі
- JSON сторінок, вкладені блоки, зображення та їхні підписи зберігаються в SQLite. Зображення не залежать від тимчасових URL Notion. Звичайний backup.sh включає ці дані; для переїзду переносіть базу та .env за наявною інструкцією.
- Це знімок на час імпорту. Наступні зміни в Notion самі не змінюють надіслану копію. Для заміни: правкер → «Змінити» біля вислуханого актора → повторний імпорт → сповіщення. Старі копії не перезаписуються.
- Зберігаються заголовки карток, абзаци, форматування, списки, чекбокси, цитати, згортання, колонки, прості таблиці та вкладені блоки. Вигляд адаптований до додатка, а не точна копія інтерфейсу Notion.
- Коментарі, історія редагувань, інтерактивні віджети, вкладені бази та відео/аудіо/PDF не відтворюються повністю. Для таких блоків є попередження та посилання на оригінал. Графічні формули показуються текстом. Іконки сторінок, окрім emoji, не копіюються.
- Перед підтвердженням перевірте серію: якщо вкладка містить декілька серій, будуть отримані всі картки цього псевдоніма в ній. Додайте збережений фільтр серії у Notion, якщо це потрібно.
- Ліміт: 200 карток актора / 5000 блоків / 20 рівнів вкладеності; растрове зображення до 20 МБ, сумарно 100 МБ на імпорт. SVG не копіюються. Якщо копіювання зображення не вдалося, весь імпорт не застосовується.
- Незавершені копії старші 7 днів очищуються під час запуску сервера. Опубліковані копії зберігаються.

## Перевірка
Автотести використовують підставні відповіді Notion: перевіряють фільтрацію актора, пагінацію, вкладені зображення, збереження байтів, відмову при неповному імпорті, захист одержувача та HTML. Доступ до вашої приватної бази не перевірений: потрібні налаштування вище та пробний імпорт однієї людини.

Офіційна документація: https://developers.notion.com/guides/data-apis/working-with-views
